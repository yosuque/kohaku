Python port (`kohaku-ui` on PyPI): new `kohaku.storage.redis` subpackage (extra `redis`, redis-py's asyncio client), the port of this package, data-compatible with it so a TypeScript host and a Python host can serve one Redis. `create_redis_storage_port(url=… | client=…, key_prefix="kohaku")` is a full `StoragePort`: the Spec cache, lineage (append-only hash plus a sorted-set index per field, with the bounded chunked reads behind `list_lineage` and `page_lineage`), promotion state and fixations (one key per tenant and id, with all-tenant and per-tenant indexes), the batch `put_promotion_states`, and the optional compare-and-set (`supports_compare_and_set`, `expected_revision`, `StorageConflictError`) as WATCH / MULTI / EXEC on a connection pinned to the transaction by redis-py's `Pipeline.watch` — no Lua, like the TypeScript adapter. `create_redis_revocation_store` is the Redis `CapabilityRevocationStore` (`{prefix}:revoked:{jti}` with its own TTL). The key layout, the index entries and the stored JSON text are pinned against the TypeScript adapter by the cross-language golden (`storageLayout`), and the `storage-redis` `python-interop` test starts the Python adapter against the same Redis, writes with one language and compare-and-sets with the other. `kohaku.spec` gains `normalize_tenant` and the shared lineage filter (`matches_lineage_filter`, `apply_lineage_limit`, `LINEAGE_PAYLOAD_INDEX_FIELDS`); the Python sample host selects the backend with `KOHAKU_STORAGE=redis` and `KOHAKU_REDIS_URL` like the TypeScript sample. The TypeScript `@kohaku-ui/storage-redis` is unchanged: it carries no code change in this entry and is listed only because a changeset must name an npm package, and the fixed group moves npm and PyPI to the same version. See `python/README.md`.
