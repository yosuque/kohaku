Python port (`kohaku-ui` on PyPI): new `kohaku.authz_hmac` subpackage, the port of this package, moved out of `examples/sales-api` into the library. `create_hmac_authz_port(secret, *, require_jti=False, require_tenant=False, revocation=None)` issues and verifies the capability token with the full claim set `sub / scopes / exp / jti [/ tenant]` and gains pre-expiry revocation (`revoke_capability`, a `CapabilityRevocationStore` Protocol and `RevokeCapabilityResult` in `kohaku.spec`, `create_memory_revocation_store`, `require_jti`); `create_hmac_approval_port(secret, *, store=None)` and `create_memory_approval_store()` are the approval-token port (v2 prefix, derived MAC key, TTL clamp, self-approval refusal) and its single-use store, now with the TS throttled sweep. Tokens are byte-identical to the TypeScript ones — the cross-language golden (`authzHmac`) pins a TS-issued capability and approval token set that the Python port verifies and re-issues exactly; as part of that, a tenant-less approval token now omits the `tenant` claim instead of writing `null`. `DEFAULT_CAPABILITY_TTL_SECONDS` moves to `kohaku.spec` (still re-exported by `kohaku.host_core`), and the library port has no default secret (the old sample port defaulted to a dev secret). The TypeScript `@kohaku-ui/authz-hmac` is unchanged: it carries no code change in this entry and is listed only because a changeset must name an npm package, and the fixed group moves npm and PyPI to the same version. See `python/README.md`.
