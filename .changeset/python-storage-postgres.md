Python port (`kohaku-ui` on PyPI): new `kohaku.storage.postgres` subpackage (extra `postgres`, psycopg 3 and its connection pool), the port of this package, data-compatible with it so a TypeScript host and a Python host can serve one database. `create_postgres_storage_port(connection_string=… | pool=…, schema="public", migrate=True)` is a full `StoragePort` on the same tables, indexes and `POSTGRES_SCHEMA_VERSION` as the TypeScript adapter, migrated under the same advisory lock (`kohaku:schema:{schema}`) with the same retry backoff, concurrent index build and `migrate=False` read-only check, so both languages can start against one database at once; every JSON payload column stays `text`. The optional compare-and-set (`supports_compare_and_set`, `expected_revision`, `StorageConflictError`) is one conditional statement whose row count decides (`(payload::jsonb ->> 'revision')` predicate, `INSERT … ON CONFLICT DO NOTHING`), with no DDL change. `create_postgres_revocation_store` is the Postgres `CapabilityRevocationStore`. The generated DDL (seven schema names), the correlation-id digest and the stored JSON text are pinned byte for byte against the TypeScript adapter by the cross-language golden (`storageLayout`), and the `storage-postgres` `python-interop` test starts the Python adapter against the same database, writes with one language and compare-and-sets with the other. The Python storage contract suite (`tests/storage/_contract.py`) runs the TypeScript contract's cases against memory, file, redis and postgres; the Python sample host selects the backend with `KOHAKU_STORAGE=postgres`, `KOHAKU_POSTGRES_URL` and `KOHAKU_POSTGRES_SCHEMA` like the TypeScript sample. The TypeScript `@kohaku-ui/storage-postgres` is unchanged: it carries no code change in this entry and is listed only because a changeset must name an npm package, and the fixed group moves npm and PyPI to the same version. See `python/README.md`.
