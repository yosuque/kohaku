# @kohaku-ui/host-a2ui

A2UI-compatible profile for kohaku: converts UI Specs and Spec patches into A2UI messages, and
ingests a third-party A2UI agent's surface back into a kohaku UI Spec. [Draft], out of scope for
conformance checking — see [spec/SPEC.md](https://github.com/yosuque/kohaku/blob/main/spec/SPEC.md) §6.3.

Part of [kohaku](https://github.com/yosuque/kohaku), a reference implementation of the
[Kohaku Protocol](https://github.com/yosuque/kohaku/blob/main/spec/SPEC.md): UI treated as data
(a declarative UI Spec), with generation separated from rendering.

```bash
npm install @kohaku-ui/host-a2ui zod
```

The packages in this scope share a single version and are designed to be installed together.

## Outbound: kohaku Spec → A2UI

`toA2ui(spec)` / `patchToA2ui(patch, appliedSpec?)` follow **A2UI v0.9.1** by default (byte-identical
output, golden-tested), stashing kohaku-specific information into a `KohakuSidecar` since v0.9.1's wire
is strict and forbids extension keys. Passing `{target: "v1.0"}` follows the **A2UI v1.0 RC** instead
(bundles `components`/`dataModel` into a single `createSurface`, no `theme`); `{target: "v1.0",
catalogMode: "split"}` additionally stamps a per-component `catalogId` for kohaku's own (non-basic)
components, and `{target: "v1.0", rendererFunctions: true}` projects a client-local `state.set` as a
`kohaku.setState` catalog function call instead of a generic event (declared by
`buildKohakuCatalogDocument`). `fromA2uiEvent(action)` converts an A2UI client action back into a kohaku
`GuiAction`.

## Inbound: A2UI agent → kohaku Spec (ingest, a governance proxy)

`fromA2ui(surfaceState, opts)` converts an accumulated third-party surface (fold inbound messages with
`reduceSurfaces`, schema-validated by `parseInboundA2uiMessage`) into a kohaku `UISpec`: it restores a
component losslessly when a `KohakuSidecar` is available (kohaku's own prior output, re-ingested),
otherwise maps it best-effort (Column/Row → `layout.stack`, `Text` → `text.heading`/`presentMarkdown`,
`Button` → `action.button`, a recognized catalog type verbatim). Content it cannot represent (an unknown
component, a data-bound repeated template, a computed function-call value) becomes a deterministic
`presentMarkdown` placeholder by default, or fails the whole conversion with `unmappable: "reject"` —
**never regenerated by an LLM**. `action.event` on any component becomes a real, interactive kohaku
`EventBinding` (`emit: "action.invoke"`); `toA2uiClientAction(guiAction)` routes a resulting interaction
back to the original agent.

`createA2uiIngest({storage, recorder, fixations, agentId, ...})` wires this into a caching + lineage
pipeline over structural subsets of `StoragePort` / `@kohaku-ui/lineage`'s `RestViewRecorder` /
`Fixations` (so this package gains no runtime dependency on either):

```ts
import { createA2uiIngest } from "@kohaku-ui/host-a2ui";
import { createFileStoragePort } from "@kohaku-ui/storage-memory";
import { createLineage, createViewRecorder, createFixations } from "@kohaku-ui/lineage";

const storage = createFileStoragePort("./.data");
const lineage = createLineage({ storage });
const ingest = createA2uiIngest({
  storage,
  recorder: createViewRecorder(lineage),
  fixations: createFixations({ lineage, storage }),
  agentId: "vendor-checkout-agent", // from your own auth, never from the message payload
});

const { spec, cache, losses } = await ingest.ingest(vendorMessages, {
  intent: { canonical: "vendor.checkout", params: { orderId } }, // see the note below
});
```

**Pass an explicit `intent`.** Without one, `ingest()` derives a default canonical name from
`surfaceId` (`a2ui.<agent_slug>.<surface_slug>`); since a real agent typically mints a fresh `surfaceId`
per session/connection, that default almost never repeats, so the Spec cache almost never hits and the
same surface never accumulates into one fixation-proposal candidate. Pass a product-meaningful,
request-stable Intent instead whenever the ingested content represents "the same logical view" across
calls.

`ingest()` records `view.composed` (`tier: "L1"`, `composedBy: "a2ui-ingest"`, `model: "a2ui:<agentId>"`)
on every call and `view.fallback` whenever a loss occurred, so ingested content shows up in Lineage /
Analytics like anything else; `ingest.fixate(surfaceId, approver)` pins the latest outcome the same way
any other L1 Spec gets fixated to L0.
